# First-question latency and provider resilience

The first question is generated by a four-model chain:

1. `meta_planner` — selects information dimensions.
2. `proposal_generator` — emits candidate questions as one strict CSV batch.
3. `proposal_evaluator` — evaluates candidates in parallel per target gap.
4. `proposal_ranker` / `decision_policy` / `question_delivery` — choose and deliver.

Each node is wrapped by `agent.graph.timed_node`, which records a
`first_question_<node>` timing span in the read model. These spans use the
monotonic backend clock and can be inspected through the researcher session
timeline. They are never compared directly with browser `performance.now()`
spans.

## Latency guardrails

| Setting | Default | Purpose |
| --- | --- | --- |
| `CVI_LLM_MAX_RETRIES` | `0` | Prevent provider SDK retries from honouring multi-minute `Retry-After` headers. |
| `CVI_LLM_REQUEST_TIMEOUT` | `12` | Bound each provider request. |
| `invoke_with_rate_limit_retry` attempts | `2` | Bound application-level rate-limit retries. |
| Retry delay | `0.5s`, capped at `1s` | Keep the first question in the prior 6–8s range instead of sleeping 15s+. |

Raise the retry settings only on a stable paid tier. The defaults favour a
predictable live interview over exhaustive provider retries.

## Deterministic fallbacks

Rate limits must not fail a live interview. Each model boundary has a
model-free fallback:

- `meta_planner` returns a fixed experience-focused plan.
- `proposal_generator` returns three neutral questions per target.
- `proposal_evaluator` assigns neutral `medium` evaluations to the affected
  target group.

Fallbacks preserve provider independence: they are pure Python and contain no
SDK or network calls. They are also auditable as ordinary graph state and
timing spans.

## Known customer segments

When `customer_segment` or `target_audience` is supplied at interview creation,
the relationship and awareness are treated as established facts:

- Meta-plan prompts omit `Product relationship` and `Product awareness`.
- Proposal prompts explicitly prohibit relationship/awareness questions.
- Generated questions are deterministically filtered; matching questions are
  replaced with neutral experience questions before evaluation.
- Evaluator prompts do not reward questions that re-establish the audience.

This prevents first questions such as
`What is your current relationship with UI Check Product, if any?` or
`How did you first hear about UI Check Product?` for known customer segments.
